# 全量备份与安全合并

入口：`/bookkeeping/data-transfer`，也可从登录后的“备份／合并”进入。

- 需要有效账本会话，并再次输入共享账本口令。管理授权绑定当前会话，有效期 15 分钟。
- 导出包含 `ledger_entries`（两人的个人账目和家庭账目）、`savings_accounts`、`family_projects`、`project_expenses`。
- 备份和预览只读取数据，不调用种子初始化，不修改业务表。备份文件包含私人财务信息，不得放入 Git、公共静态目录或公开附件。
- 支持本入口备份以及完整的 `bookkeeping-sites-db-snapshot-v1` 表快照。缺表、重复 ID、无效分值或缺少关联项目时拒绝文件，不截断字段。

## 操作顺序

1. 在目标网站登录并解锁，下载当前数据库的全量备份。
2. 载入另一端的完整备份，点击“预览合并”。
3. 核对新增、相同跳过和冲突清单。任何内容冲突都会阻止整批合并。
4. 再保存与本次预览对应的合并前备份，输入确认文字后提交。
5. 保存合并后备份，复核所有来源记录已匹配，当前端原有的额外记录仍然保留。

## 数据保护

- 不删除目标记录，不按余额求和覆盖账户，不根据时间戳推测哪一边正确。
- 有来源编号的账目优先按来源编号匹配；无编号记录按业务内容的多重集比较，保留真实重复记录的数量。完全相同的两条独立记录与历史副本之间无法自动区分，需核对预览清单。
- 同名账户、同名专项、同日同名账目等内容不同，列为冲突，不自动覆盖或双算。
- 唯一例外是明确的系统默认项目：唯一名称“新房装修”、预算 0、默认说明及状态、system 创建且没有支出。可用来源填充该占位项目，保留目标项目 ID。
- 新记录保留来源业务字段、操作人和时间戳，重新分配数据库 ID 并映射专项引用。
- 预览令牌绑定来源、目标全量快照、会话、站点及有效期。提交时重新计算计划，并在同一个 D1 batch 事务内检查全部业务列及 AUTOINCREMENT 序列，然后写入；并发修改或任一 SQL 失败会回滚全批次。
- 网络中断后先重新备份、预览核对，不直接重试旧提交。重复预览同一来源不会重复新增已匹配记录。

这是一次性合并功能，不是两个独立数据库之间的持续双向同步。完成后应选择一个正式入口持续记账，避免两端再次分叉。
